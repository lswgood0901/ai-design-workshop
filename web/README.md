# 실습용 이미지 워크스페이스

HTML, CSS, JavaScript ES modules로 구성된 브라우저 인터페이스입니다. 프레임워크나 빌드 과정 없이 사용할 수 있습니다. 저장소의 실행 안내에 따라 로컬 서버를 켜고 브라우저로 접속합니다. HTML 파일을 더블클릭하는 `file://` 실행은 지원하지 않습니다.

## 두 단계로 사용하기

1. **인터페이스 실습 모드**: 기본 실행 방식입니다. 지시문, 참조 이미지, 미리보기, 기록 저장을 확인합니다. 출력에 `UI TEST` 표시가 들어가며, AI가 생성한 이미지가 아닙니다.
2. **GPU API 모드**: 오른쪽 위 **인터페이스 실습 모드 → 실행 방식**에서 전환합니다. 강사가 안내한 HTTPS 서버 주소와 API 키를 입력합니다. 로컬 API를 구성한 경우에는 `http://localhost:포트`도 사용할 수 있습니다.

API 키는 현재 탭의 메모리에만 유지합니다. 새로고침 후에는 다시 입력해야 합니다. HTML, 코드, Git, 생성 기록 또는 내보내는 JSON 파일에 키를 넣지 않습니다.

## 지원하는 기능

- 텍스트를 이용한 이미지 생성
- PNG/JPG/WebP 참조 이미지 1~4장을 이용한 편집
- 첫 번째 이미지의 수동 브러시 마스크, 마스크 PNG 저장
- 로컬 SlimSAM 모델을 이용한 포함/제외 지점 선택
- 마스크 영역만 생성 결과로 교체하는 브라우저 후처리
- WebP 출력, JSON 작업 기록 다운로드
- IndexedDB에 이미지·지시문·생성 조건 보관
- 이전 결과를 다시 편집 입력으로 사용
- 전체 GPU 준비/실행/대기 상태 표시와 응답 대기 중단

이미지 히스토리는 **현재 브라우저의 현재 사이트 저장소**에 보관됩니다. 다른 브라우저·다른 서버 주소에서는 보이지 않으며, 사이트 데이터를 지우면 사라질 수 있습니다. 필요한 결과는 내려받으세요.

## 실제 API 계약

이 실습 서버는 동기 방식입니다. BFL의 상용 비동기 API와 다릅니다.

- `POST /v1/generate` 또는 `POST /v1/edit`
- 인증: `Authorization: Bearer <CLASS_API_KEY>`
- 응답: `image/webp` 바이너리
- 상태: `GET /v1/status`
- 크기: 16의 배수, UI에서는 최대 약 1MP
- 4 steps, guidance 1.0, 한 요청에 한 장

`api.mjs`가 통신을 담당하고 `core.mjs`가 입력값을 검사합니다. 입력 이미지는 `input_image`, `input_image_2` … `input_image_4`에 data URL로 넣습니다. 외부 이미지 URL은 보내지 않습니다.

상태 표시는 **전체 서버 상태**이며 개인별 대기 순번/진행률이 아닙니다. “응답 기다리기 중단”은 브라우저의 대기를 중단합니다. 이미 서버가 접수한 추론까지 취소하지는 않습니다.

## 마스크와 SlimSAM

저장소 다운로드 안내에 따라 `public/models/Xenova/slimsam-77-uniform/`에 모델을 준비합니다. “SlimSAM 로드”를 누르면 Transformers.js 3.8.1 실행 라이브러리를 jsDelivr에서 불러오고, 모델 가중치는 위 로컬 폴더에서 읽습니다. 처음 사용하는 브라우저에는 라이브러리와 WASM 런타임 다운로드를 위한 인터넷 연결이 필요합니다.

- 모델: `Xenova/slimsam-77-uniform`
- 실행: 브라우저 WASM, `q8`, 단일 스레드
- 수동 브러시는 모델 다운로드나 NVIDIA/CUDA 없이 작동

FLUX.2 [klein] API에는 마스크를 전달하지 않습니다. **선택 영역 합성**은 생성된 전체 이미지와 원본을 브라우저에서 합치는 후처리이며, 모델의 마스크 인페인팅 기능이 아닙니다. 원본과 결과 비율이 다르면 합성하지 않고 생성 결과를 보관합니다. 형태가 크게 달라지면 경계가 어긋날 수 있으므로 결과를 확인해야 합니다.

## 확인

```sh
node --test tests/web.test.mjs
```

요청 형식, 이미지/시드/크기 제한, 키 비노출, 로컬 마스크 합성, WebP 응답과 오류 처리, 전체 대기 상태 표기를 확인합니다. GPU 추론과 브라우저 모델 로드는 실제 실행 환경에서도 확인해야 합니다.
