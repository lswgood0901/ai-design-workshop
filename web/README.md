# 이미지 생성·편집 인터페이스

HTML, CSS, JavaScript로 만든 기본 웹 예제입니다. 프로젝트 루트에서 실행합니다.

```bash
python scripts/serve.py
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다.

## 실행 방식 선택

오른쪽 위 **실습 환경 연결**에서 실행 방식을 고릅니다.

| 실행 방식 | 준비 | 화면에서 할 일 |
|---|---|---|
| 인터페이스 실습 | 웹 페이지 실행 | 프롬프트, 이미지 입력, 미리보기와 히스토리 확인 |
| 로컬 모델 | [로컬 실행 안내](../docs/local-setup.md)에 따라 4비트 모델과 로컬 API 실행 | **로컬 모델** 선택 → 적용 |
| GPU 서버 | 수업에서 안내받은 주소와 키 | **GPU 서버** 선택 → 주소·키 입력 → 적용 |

로컬 모드는 현재 컴퓨터의 `http://127.0.0.1:8032`에 연결합니다. Mac의 Apple Silicon은 MLX 4비트, Windows의 NVIDIA GPU는 CUDA 4비트를 사용합니다. API 연결은 실행 방식에 맞춰 자동 설정되며, GPU 서버 주소와 키는 같은 탭에서 모드를 바꿔도 유지됩니다.

## 로컬 생성·편집

1. **로컬 모델**을 적용하고 화면 아래의 준비 상태와 여유 메모리를 확인합니다.
2. **이미지 생성**에서 영어로 정리한 지시문을 입력하고 실행합니다. 로컬 기본 출력은 **512 × 512, 4 steps**입니다.
3. 결과의 **편집 입력으로 사용**을 누릅니다.
4. 바꿀 부분과 유지할 부분을 영어로 입력하고 **이미지 편집**을 실행합니다. 처음에는 참조 이미지 한 장으로 시작하세요.
5. **이미지 저장**과 **기록**으로 WebP 이미지와 JSON 작업 기록을 내려받습니다.

한 번에 한 작업을 실행합니다. 로컬 API가 시작 전 여유 메모리를 확인하고 실행 중 메모리 부족을 감지하면 해당 작업을 중단합니다. 중단 이유가 화면에 표시되면 사용하지 않는 앱을 닫고, 여유 메모리를 확인한 뒤 실행 버튼을 다시 누르세요. 시작 기준은 9 GiB, 실행 중 여유 메모리 기준은 4 GiB입니다.

이미지 히스토리는 현재 기기와 브라우저에 저장됩니다. 페이지를 새로 열면 실행 방식을 다시 선택합니다.

## 기본 기능

- 생성·편집 모드와 참조 이미지 1–4장
- 이미지·프롬프트·seed·시간을 저장하는 히스토리
- 이전 결과를 편집 입력으로 재사용
- WebP 이미지·JSON 기록 다운로드
- GPU 서버의 전체 실행·대기 상태 또는 로컬 모델의 메모리·준비 상태 표시

## 선택 기능 · 영역 합성

편집 결과 중 선택한 부위를 원본에 합성합니다. 표면의 색상·소재 변경에 활용합니다. 브러시로 영역을 지정하거나, [SlimSAM](../docs/segmentation.md)을 준비해 포함·제외할 점을 클릭합니다.

## 구현 정보

`api.mjs`는 통신, `core.mjs`는 입력값 검사를 담당합니다. 이미지 편집은 원본 data URL과 프롬프트를 전달하고 WebP 응답을 받습니다. 로컬 모드와 GPU 서버 모드는 같은 생성·편집 경로를 사용합니다. 로컬 모드의 주소와 연결 값은 `core.mjs`의 `LOCAL_CONNECTION`에 정의되어 있습니다.

```bash
node --test tests/web.test.mjs
```
