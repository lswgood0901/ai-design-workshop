# 1단계 · 이미지 생성·편집 인터페이스

목표는 디자인 작업에 필요한 화면과 기록 방식을 직접 정하는 것입니다. 14:30–15:15, 45분 동안 모델이 연결되지 않은 상태에서 구현합니다.

| 시간 | 작업 |
|---|---|
| 14:30–14:35 | 작업 폴더 열기, 도구 로그인, 실행 경로 확인 |
| 14:35–14:50 | 프롬프트 입력·이미지 입력·결과 영역 구현 |
| 14:50–15:05 | 히스토리 저장, 결과 재사용, 마스크 선택 |
| 15:05–15:15 | 브라우저에서 확인하고 오류·사용성 수정 |

## 필수 기능

1. **생성 / 편집 모드:** 텍스트만 입력하는 생성과 참조 이미지를 사용하는 편집을 구분합니다.
2. **텍스트 입력:** 디자인 요구, 재료, 배경, 수정 대상과 유지할 부분을 적을 수 있어야 합니다.
3. **이미지 입력:** PNG/JPEG/WebP를 올리고 미리 봅니다. 편집 모드에서는 참조 이미지가 필요합니다.
4. **결과 영역:** 결과 이미지, 실행 상태와 오류를 표시합니다. 모델 연결 전에는 `모델 미연결` 또는 `UI 테스트`라고 명확하게 표시합니다.
5. **히스토리:** 이미지·지시문·모드·seed·시간·실행 방식을 IndexedDB에 저장합니다. 새로고침 뒤에도 남아 있어야 합니다.
6. **다시 편집:** 히스토리 이미지를 편집 입력으로 불러오고 지시문을 수정합니다.
7. **저장:** 이미지와 작업 기록을 내보냅니다. 접속 키는 기록에 포함하지 않습니다.

## 마스크

시간이 되면 [경량 분할 모델](segmentation.md)의 클릭 선택을 추가합니다. 실패해도 붓으로 추가·지우기와 PNG 마스크 저장을 사용할 수 있게 합니다. 마스크만 만드는 단계와 실제 편집 단계는 구분합니다.

## 확인할 동작

- 입력이 비어 있거나 편집 이미지가 없으면 이유를 알려주는가?
- 긴 프롬프트와 세로 이미지도 화면에 잘 보이는가?
- 이미지를 올리고 히스토리에서 다시 불러올 수 있는가?
- 새로고침 후 히스토리는 남고, 키는 저장되지 않는가?
- 실행 중 다시 누르는 것을 막고 실제 상태만 표시하는가?

화면 배치·분위기·추가 입력 항목은 각자의 디자인 업무에 맞게 바꿉니다. 첫 시간에 회원가입, 협업 서버, 결제나 복잡한 프로젝트 관리 기능은 필요하지 않습니다.
